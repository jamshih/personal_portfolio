01 / WRONGBOOK

WrongBook

A native iOS app for a familiar study failure: you photograph a question you got wrong, then never look at the photo again. WrongBook keeps the question, the mistake, the correction, and later attempts together.

What I built
Swift app, Supabase backend, AI scan pipeline, subscriptions, account flows
Hard parts
OCR + math notation, diagram extraction, account isolation, sync, production reliability
Stack
Swift · Vision · Supabase · StoreKit · Edge Functions
Private codebase. I keep the app source private while I work toward the public release.
ONE MISTAKE, KEPT AS ONE MEMORY
1
Original questionThe source problem, including notation and diagram.
2
Why it went wrongThe student’s reasoning, wrong answer, and the actual failure mode.
3
CorrectionThe concept and corrected solution stay attached to the mistake.
4
Retry laterFuture attempts become part of the same learning history.
02 / SEARCHRECALL

SearchRecall

An English-learning web app that turns selected Chrome searches and dictionary lookups into vocabulary cards and review practice. The point is not to archive everything you browsed; it is to reuse the English you already encountered.

What I built
Web app, Chrome Helper, import flow, search/history processing, cloud backend
Privacy model
A user-started scan reads history locally, filters supported learning records, then sends only those records to SearchRecall.
Scale tested
Chrome History / Takeout imports with 100k+ records
Open search-recall.com ↗
Private codebase. The live product is public.
FROM A SEARCH TO SOMETHING YOU CAN REVIEW

→
02 · keepUseful English becomes a learning record
→

The Chrome Helper only runs after the user starts a scan. Filtering happens locally before supported learning records are sent.
